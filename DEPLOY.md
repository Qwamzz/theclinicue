# Deploying Clinicue

**Time needed:** about 10 minutes, most of it waiting for the first build.
**Cost:** free.

You need two free accounts: **GitHub** (to host the code) and **Render** (to run it).
Everything Render needs is already in `render.yaml`.

---

## Step 1 — Put the code on GitHub

The repository is already initialised and committed locally. You only need to push it.

### 1.1 Create an empty repository

1. Sign in at **https://github.com** (create an account if you need one).
2. Click **+** (top right) → **New repository**.
3. **Repository name:** `clinicue`
4. **Visibility:** *Public* is simplest — the examiner can then read the source without being added as a collaborator. Choose *Private* if you prefer, but you will need to invite the examiner.
5. **Do not** tick "Add a README", "Add .gitignore" or "Choose a licence". The repository must be empty, or the push will be rejected.
6. Click **Create repository**.

### 1.2 Push

Copy the URL GitHub shows you (it looks like `https://github.com/YOUR-USERNAME/clinicue.git`), then in a terminal, from the project folder:

```bash
git remote add origin https://github.com/YOUR-USERNAME/clinicue.git
git push -u origin main
```

If GitHub asks for a password, it wants a **personal access token**, not your account password:
**Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token**, tick the `repo` scope, and paste the token as the password.

**Check:** refresh the GitHub page. You should see `app/`, `docs/`, `tests/`, `README.md` and `render.yaml`.

> The `.gitignore` already excludes the database, `.env`, coverage output and the virtual environment, so nothing sensitive is pushed. There are no secrets in the repository — the session key is generated by Render at deploy time.

## Step 2 — Deploy on Render

### 2.1 Create the service

1. Sign in at **https://render.com** — choose **Sign in with GitHub**, which saves a step later.
2. From the dashboard, click **New +** → **Blueprint**.
3. Render lists your GitHub repositories. Find **clinicue** and click **Connect**.
   - If it is not listed, click **Configure account** / **Configure GitHub App** and grant Render access to the repository.
4. Render reads `render.yaml` and shows a service called **clinicue**.
5. Give the blueprint a name (anything — `clinicue` is fine) and click **Apply** / **Create Resources**.

You do **not** need to type a build command, start command, environment variables or a health check path. They are all in `render.yaml`, including `CQ_SECRET_KEY`, which Render generates and stores for you.

### 2.2 Wait for the first build

Open the service and watch the **Logs** tab. The first build takes 2–4 minutes. You are looking for, in order:

```
==> Installing dependencies
Successfully installed Flask-3.1.3 ... PyJWT-2.13.0 gunicorn-26.0.0
==> Running 'python -m app.seed && gunicorn ...'
Seeded /tmp/clinicue.sqlite3
  users           11
  services        5
  practitioners   3
[INFO] Starting gunicorn 26.0.0
[INFO] Listening at: http://0.0.0.0:10000
==> Your service is live 🎉
```

Your URL appears at the top of the page: `https://clinicue.onrender.com`
(Render adds a suffix if the name is taken, e.g. `https://clinicue-a1b2.onrender.com`.)

### 2.3 Check it works

Open `https://YOUR-URL/api/health`. You should see:

```json
{"service":"clinicue","status":"ok","database":"ok","environment":"production", ...}
```

Then open `https://YOUR-URL` and sign in as `admin@clinicue.health` / `Admin#2026`.

## Things worth knowing before the examiner opens it

### The free service sleeps

After 15 minutes with no traffic, Render's free tier spins the service down. The next visit takes **30–50 seconds** to wake up, and looks like a slow page load rather than an error.

Two ways to handle it:

- **Simplest:** add a line to `Deployment_and_Source_Links.txt` saying the first load may take up to a minute. Honest and costs nothing.
- **Better:** open the URL yourself a few minutes before the demonstration or viva so it is already awake.

### Data resets

Because the free tier has no persistent disk, the database is recreated on every restart, including after a sleep. The demonstration accounts are re-seeded automatically, so **the credentials always work** — but bookings made during a demonstration may vanish after a sleep.

This is deliberate, documented, and is technical debt item **TD-01**, classified CRITICAL, with a hard gate against real patient data. It is not something to hide from the examiner; it is a worked example of managed technical debt.

To fix it properly (needs a paid instance, about \$7/month):

1. In `render.yaml`, uncomment the `disk:` block at the bottom.
2. Change `CQ_DATABASE_PATH` to `/var/data/clinicue.sqlite3`.
3. Commit, push. Render redeploys with a persistent volume.

### If the build fails

| Symptom in the logs | Cause | Fix |
|---|---|---|
| `No such file or directory: 'render.yaml'` | Blueprint pointed at the wrong repository or branch | Check the repository, and that the branch is `main` |
| `CQ_SECRET_KEY must be set in production` | The env var did not get generated | Service → **Environment** → add `CQ_SECRET_KEY` with any long random string |
| `ModuleNotFoundError: flask` | Build command did not run | Service → **Settings** → Build Command should be `pip install -r requirements.txt` |
| `Permission denied: '/var/data'` | Database path points at a disk that is not mounted | `CQ_DATABASE_PATH` should be `/tmp/clinicue.sqlite3` on the free tier |
| Health check failing, service restarting | App started but `/api/health` is unreachable | Confirm the start command binds `0.0.0.0:$PORT` — it does in `render.yaml` |

### Redeploying after a change

```bash
git add -A
git commit -m "your message"
git push
```

Render rebuilds automatically on every push to `main`.

## Alternative: Docker on your own server

If you would rather not use Render:

```bash
docker build -t clinicue .

docker run -d --name clinicue -p 8000:8000 \
  -e CQ_SECRET_KEY="$(python -c 'import secrets;print(secrets.token_urlsafe(48))')" \
  -e CQ_COOKIE_SECURE=true \
  -v clinicue-data:/data \
  --restart unless-stopped \
  clinicue

docker exec clinicue python -m app.seed
```

The `-v clinicue-data:/data` volume is what makes the data survive a restart — this is the TD-01 fix in its simplest form.

Put a reverse proxy with TLS (Caddy or nginx) in front of it. `CQ_COOKIE_SECURE=true` requires HTTPS; over plain HTTP the browser will discard the session cookie and sign-in will appear to fail silently.
